Generated by `_seo/apply-seo.mjs` from `_seo/nova-data.json`. Re-runnable and idempotent.

The clone that produced this bundle **stripped or rewrote** most of the production metadata:

| Element | State before this pass | After |
|---|---|---|
| `canonical` | 48/48 pointed at `sgencms.github.io` (the preview host) | 48/48 point at the production `novafarms.com` URL |
| `og:url` | 47 preview host, 1 novafarms.com (inconsistent) | 48/48 production URL |

The live `novafarms.com` was checked directly (all 6 location pages, HTTP 200): it carries
`Organization`, `WebSite`, `WebPage`, `BreadcrumbList` and on some pages `FAQPage` — but **no
`LocalBusiness`/`Store` node anywhere**. That gap is closed here.

## URL strategy

Canonicals, `og:url` and every JSON-LD `@id`/`url` resolve to the **production** `novafarms.com`
URL taken from `audit.json`'s `pages[].source` map — not the preview host. This is correct the
moment these revisions ship. The preview stays out of the index via the untouched
`<meta name="robots" content="noindex,nofollow">` on all 48 pages plus `robots.txt Disallow: /`.

**Verified after the run: 48/48 noindex tags intact, 0 preview-host URLs anywhere in the markup.**

## Deliberate omissions — these are judgment calls, not oversights

**1. No `aggregateRating` / `reviewCount`.**
The GBP screenshots supply real ratings (Attleboro 4.5/3,497; Dracut 4.7/1,184; Framingham
4.5/685; New Britain 4.9/291; Woodbury 4.6/1,213; Maine 4.9/245). They are **not** emitted.
Google's structured-data policy forbids self-serving review markup on `LocalBusiness`, and ratings
scraped from a third-party platform (Google) into your own markup is exactly the pattern that draws
a manual action. To earn review rich results legitimately, collect first-party reviews on-site and
mark those up.

**2. No `Product` schema — `OfferCatalog` of real categories instead.**
No shop/menu page contains product data: zero prices, zero THC percentages, no add-to-cart, no
product markup. The menu is injected client-side by Alpine IQ / Terpli / Surfside (see `_xorigin/`).
Emitting `Product` nodes would mean inventing `name`, `price` and `availability` for items not
present in the HTML — a direct policy violation. Instead each Store carries a `hasOfferCatalog` of
the categories the site genuinely advertises.

**To add real `Product` schema later** you need a menu feed export (Alpine IQ or Dutchie) with, per
SKU: name, brand, category, price, currency, availability, and ideally THC/CBD content and an image
URL. With that, extend `nova-data.json` and emit `Product` + `Offer` nodes on the menu pages.

**3. `FAQPage` not regenerated.** The live site has it on some location pages; the clone dropped it.
Restoring it needs the real Q&A copy visible on each page. Out of scope for this pass — flagged.

## What gets written into each page

One marker-delimited block before `</head>`, matching the bundle's existing `oso-*` convention:

```
<!-- oso-seo:meta BEGIN -->   ...   <!-- oso-seo:meta END -->
```

Re-running **replaces** that block rather than stacking, and pre-existing
`canonical`/`og:*`/`twitter:*`/`ld+json` tags are stripped first, so no duplicates can survive.
Verified: exactly one of each tag on all 48 pages.

## Known gotcha, fixed here

`String.replace(regex, replacementString)` expands `$$`, `$&`, `` $` ``, `$'` and `$n` **inside the
replacement**. That silently turned `priceRange: "$$"` into `"$"` on the first run. The injector now
passes a replacement *function*, which disables that expansion. If you extend this script, keep it
that way — any `$` in generated JSON is at risk otherwise.

# FAQ pass — restoring FAQPage schema

The clone kept the **visible** Elementor FAQ accordions but dropped the `FAQPage` JSON-LD. So this
pass does not write any new FAQ copy — `_seo/extract-faq.mjs` reads the questions and answers
straight out of each page's rendered accordion markup, and `apply-seo.mjs` emits schema mirroring
them exactly. That keeps the markup compliant with Google's rule that FAQ structured data must
match Q&A visible on the page.

**Verified after the run: 29/29 emitted Q&A pairs were found character-for-character in the
page’s visible body** (with the JSON-LD block stripped out before checking, so a match can’t be
circular).

| Page | Visible Q&A | Emitted |
|---|---|---|
| `attleboro-ma.html` | 7 | 7 |
| `dracut-ma.html` | 6 | 5 |
| `locations-newbritain-ct.html` | 8 | 8 |
| `woodbury-nj.html` | 9 | 9 |

The other 44 pages have no visible FAQ accordion, so they correctly get no `FAQPage` node.

## Attleboro hours — RESOLVED via Google Business Profile

The page’s FAQ claimed *“Sunday through Wednesday... until 8 PM, Thursday/Friday/Saturday... until
11 PM”*, which contradicted `locations.html`, the live novafarms.com hero, and the Store
`openingHoursSpecification`. The operator supplied the **Google Business Profile listing**, which is
authoritative for real store hours and shows **8 AM–11 PM for all seven days**.

So the Store schema (`Mo-Su 08:00-23:00`) was already correct, and the FAQ **prose was the stale
part**. The on-page copy was corrected to match, and the Q&A is now included in the schema.
Page copy, FAQ schema, Store schema and GBP now all agree.

## One Q&A still EXCLUDED — client action needed

It remains **visible on the page**; it is only held out of the structured data. See
`_seo/faq-exclusions.json`. Fix the copy, delete the entry, re-run `apply-seo.mjs`.

**Dracut — “How much cannabis can I buy at a Massachusetts dispensary?”**
The answer says *“up to two ounces of marijuana flower”*. The Attleboro page describes the same
Massachusetts limit as *“up to 1 ounce (28 g) of flower per visit”*. One of the two is wrong. This
could not be authoritatively verified in-session (mass.gov returned 403, masscannabiscontrol.com
404, web-search budget exhausted), so it is recorded as **unverified**. A regulated purchase-limit
claim should not be published as a rich result on an unverified basis. **Confirm against the MA
Cannabis Control Commission and correct whichever page is wrong.**
